# ex2_dependency_graph

Этап 3: построение транзитивного графа зависимостей рекурсивным BFS.
Используется стандартная библиотека Python 3. Менеджеры пакетов и сторонние
библиотеки для получения зависимостей не используются.

Запуск с репозиторием Ubuntu APT из `config.ini`:

```sh
./run.sh
```

Все пять параметров секции `[settings]` сохранены:

| Параметр | Назначение |
| --- | --- |
| `package` | Имя пакета APT; в тестовом режиме — большие латинские буквы, например `A` |
| `repository` | URL индекса `Packages`, `Packages.gz`, `Packages.xz`; в тестовом режиме — путь к JSON-файлу графа |
| `test_mode` | `true` — тестовый граф, `false` — индекс APT по URL |
| `version` | Точная версия корневого пакета APT; для тестового графа сохраняется как параметр конфигурации, поскольку JSON не содержит версий |
| `ascii_tree` | Сохранённый параметр конфигурации; на этом этапе результат выводится списком смежности |

URL индекса содержит выпуск, компонент и архитектуру, например:
`https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz`.
Булевы значения: `true/false`, `yes/no`, `on/off`, `1/0` без учёта регистра.
Все параметры обязательны. Прежние проверки INI и обработка ошибок сохранены.

## Алгоритм

`src/graph.py` обрабатывает весь текущий уровень BFS, собирает следующий
и рекурсивно вызывает обработку следующего уровня. Вершина отмечается посещённой
при добавлении в следующий уровень. Поэтому каждая вершина раскрывается один раз,
а рёбра циклов, самозависимостей и общих зависимостей сохраняются в графе.
В результат попадают только вершины, достижимые из заданного пакета.

Граф хранится как словарь списков смежности и выводится в порядке BFS:

```text
A -> B, C
B -> D
C -> D
D ->
```

Для APT корень выбирается по точным `Package` и `Version`. Транзитивные связи
извлекаются из `Pre-Depends` и `Depends`, узлами служат имена пакетов.
Для остальных пакетов используется запись из выбранного индекса; при нескольких
записях одного имени — первая. Все альтернативы через `|` включаются в граф.
Квалификаторы архитектуры и ограничения версий не входят в имя вершины.
Выбор устанавливаемой комбинации пакетов не выполняется.
Виртуальные пакеты связываются с доступными реализациями из поля `Provides`.
Если необходимого пакета и его реализаций в индексе нет, приложение сообщает
об ошибке, а не выдаёт неполный граф за полный.

Вывод только прямых зависимостей относился ко второму этапу; теперь выводится
весь достижимый граф. Функция извлечения прямых зависимостей сохранена и проверяется
тестами. Ошибки выводятся в stderr, код завершения — 1.

## Тестовый репозиторий

Вместо локального APT-индекса на третьем этапе используется JSON со списками
смежности. Все имена должны состоять из больших латинских букв. Каждая зависимость
должна быть объявлена отдельной вершиной, включая вершины с пустым списком:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["D"],
  "D": []
}
```

Пример INI:

```ini
[settings]
package = A
repository = branch.json
test_mode = true
version = 1.0
ascii_tree = false
```

Относительный путь JSON отсчитывается от папки INI. В тестовом режиме сетевых
запросов нет. В `tests/fixtures/` подготовлены пять демонстраций:

```sh
./run.sh tests/fixtures/chain.ini
./run.sh tests/fixtures/branch.ini
./run.sh tests/fixtures/cycle.ini
./run.sh tests/fixtures/self_cycle.ini
./run.sh tests/fixtures/empty.ini
```

- `chain` — цепочка `A -> B -> C`.
- `branch` — разветвление, общая зависимость `D` и недостижимая вершина `E`.
- `cycle` — цикл `A -> B -> C -> A`.
- `self_cycle` — самозависимость `A -> A`.
- `empty` — пакет `A` без зависимостей.

## Проверка

Все тесты, тестовые данные и общий скрипт запуска находятся в `tests/`:

```sh
./tests/run_tests.sh
```

Тесты работают без сети: проверяют конфигурацию, чтение и распаковку индекса,
извлечение прямых зависимостей, транзитивность, порядок BFS, циклы, виртуальные
пакеты, выбор версии корня, ошибки и все пять демонстраций через CLI.

## Структура приложения

- `src/main.py` — точка входа.
- `src/cli.py` — аргументы, вывод графа и ошибок.
- `src/config.py` — чтение INI.
- `src/validators.py` — проверка параметров.
- `src/repository.py` — чтение и распаковка данных репозитория.
- `src/dependencies.py` — разбор APT и извлечение прямых зависимостей.
- `src/apt_repository.py` — получение соседей вершин из APT-индекса.
- `src/graph_repository.py` — разбор и проверка тестового JSON-графа.
- `src/graph.py` — рекурсивный BFS.
- `src/errors.py` — исключения приложения.
