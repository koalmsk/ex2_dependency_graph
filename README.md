# ex2_dependency_graph

Python CLI для графа зависимостей Ubuntu APT и порядка их загрузки.
Только стандартная библиотека; менеджеры пакетов для сбора данных не вызываются.

## Запуск

```sh
./run.sh
./run.sh tests/fixtures/config.ini
./tests/run_tests.sh
```

В `[settings]` файла INI задаются `package`, `repository`, `test_mode`,
`version`, `ascii_tree`. В этапе 4 добавлен необязательный `load_order`:
`true` — порядок загрузки, `false` или отсутствие — список смежности графа.
`ascii_tree` сохранён из первого этапа, построение дерева пока не выполняется.
Ошибки выводятся в stderr, код завершения — 1.

## Этап 1. Конфигурация

`src/config.py`:

- `read_settings()` — читает INI и секцию `[settings]`.
- `load_config()` — собирает настройки, читает режим `load_order`, проверяет параметры.

`src/validators.py`:

- `validate_package()` — проверяет имя APT или большие латинские буквы в тестовом режиме.
- `parse_boolean()` — преобразует строку в булево значение, сообщает об ошибке формата.
- `validate_version()` — проверяет формат версии Debian/Ubuntu.
- `validate_repository()` — проверяет локальный файл или передаёт URL на проверку.
- `validate_repository_url()` — проверяет HTTP/HTTPS URL и допустимость порта.

Вывод `ключ=значение` требовался только на первом этапе.

## Этап 2. Получение данных

Для APT указывается URL индекса `Packages`, `Packages.gz` или `Packages.xz`.
Версия корневого пакета должна точно совпадать с полем `Version`.

`src/repository.py`:

- `load_repository()` — читает локальный файл или загружает данные по URL.
- `decode_repository()` — распаковывает gzip/xz и декодирует UTF-8.

`src/dependencies.py`:

- `parse_packages()` — разбирает записи и продолжения полей индекса APT.
- `find_package()` — ищет пакет по имени и точной версии.
- `get_direct_dependencies()` — извлекает `Pre-Depends` и `Depends`.

Вывод только прямых зависимостей относился ко второму этапу.

## Этап 3. Транзитивный граф

`src/apt_repository.py`:

- `dependency_names()` — извлекает имена зависимостей и всех альтернатив через `|`.
- `index_packages()` — индексирует пакеты и реализации виртуальных пакетов из `Provides`.
- `apt_dependency_reader()` — выбирает версию корня и подготавливает получение соседей.
- Вложенная `get_dependencies()` — возвращает зависимости или реализации виртуального пакета.

`src/graph_repository.py`:

- `parse_test_repository()` — проверяет JSON вида `{"A": ["B"], "B": []}`.
- `test_dependency_reader()` — проверяет наличие корня и возвращает доступ к связям.

`src/graph.py`:

- `visit_level()` — обрабатывает уровень BFS и рекурсивно переходит к следующему.
- `build_graph()` — запускает обход достижимых вершин и возвращает граф.

Каждая вершина раскрывается один раз, рёбра циклов сохраняются.
Для зависимостей APT берётся первая запись имени в выбранном индексе;
для корня — указанная версия. Отсутствующая зависимость вызывает ошибку.

## Этап 4. Порядок загрузки

`src/order.py`:

- `get_load_order()` — сортирует граф алгоритмом Кана: сначала зависимости,
  затем зависящие от них пакеты. При цикле сообщает об отсутствии порядка.

Результат включает корневой пакет последним. Это логическая последовательность
«зависимость перед пакетом»; сами архивы приложение не скачивает.
При ошибке частичный порядок не выводится.

В `tests/fixtures/config.ini` уже включён `load_order=true`.
Все случаи находятся в одном `tests/fixtures/graph.json`.
Для демонстрации меняется только `package` в тестовом INI:

| Пакет | Результат |
| --- | --- |
| `A` | `D -> B -> C -> A` — разветвление с общей зависимостью |
| `H` | `J -> I -> H` — цепочка |
| `K` | `K` — без зависимостей |
| `E` | Ошибка: цикл `E -> F -> E` |
| `G` | Ошибка: самозависимость `G -> G` |

### Сравнение с APT

Проверено с APT 2.8.4 в Ubuntu 24.04 на репозитории `noble main`.

- `fonts-dejavu-core=2.37-8`: порядок совпал —
  `fonts-dejavu-mono -> fonts-dejavu-core`.
- `bash=5.2.21-2ubuntu4`: программа обнаружила цикл
  `libc6 -> libgcc-s1 -> libc6`, APT построил план для 9 пакетов.

Программа требует строгого топологического порядка, а APT разделяет
распаковку и настройку, что позволяет планировать операции при цикле.
Кроме того, APT выбрал только `mawk`, а программа включает обе реализации
виртуального `awk`. Уже установленные пакеты APT пропускает,
программа строит весь достижимый граф.

## Управление запуском

`src/cli.py`:

- `parse_arguments()` — получает путь к конфигурации из аргументов CLI.
- `print_graph()` — выводит граф списком смежности.
- `main()` — читает настройки, строит граф, выбирает вывод графа или порядка и обрабатывает ошибки.

`src/main.py` — точка входа; `src/errors.py` содержит исключения
`ConfigError` и `RepositoryError`.

## Функции тестов

### Этап 1 — `tests/test_main.py`, класс `ConfigTests`

- `set_up()` — создаёт временную папку и настройки перед тестом.
- `write_config()` — записывает настройки в INI.
- `run_cli()` — запускает приложение с выбранным пакетом тестового графа.
- `test_valid_config_and_cli_output()` — проверяет успешный запуск и вывод графа.
- `test_cli_package_without_dependencies()` — проверяет одиночную вершину.
- `test_cli_missing_test_package()` — проверяет отсутствие корня.
- `test_invalid_values_for_every_parameter()` — проверяет ошибочные значения параметров.
- `test_missing_and_empty_parameters()` — проверяет пропущенные и пустые значения.
- `test_local_repository_relative_to_config()` — проверяет путь относительно INI.
- `test_missing_repository_file_and_directory()` — проверяет отсутствие файла и каталог вместо файла.
- `test_invalid_urls()` — проверяет некорректные URL.
- `test_file_errors()` — проверяет чтение, структуру и кодировку INI.
- `test_cli_error()` — проверяет сообщение об ошибке и код завершения CLI.

### Этап 2 — `tests/test_dependencies.py`, класс `DependencyTests`

- `set_up()` — читает тестовый индекс APT.
- `test_direct_dependencies_of_exact_version()` — проверяет зависимости разных версий.
- `test_no_dependencies()` — проверяет пакет без зависимостей.
- `test_missing_package_or_version()` — проверяет отсутствие пакета или версии.
- `test_final_stanza_and_case_insensitive_fields()` — проверяет последнюю запись и регистр полей.
- `test_malformed_index()` — проверяет ошибки структуры индекса.
- `test_plain_gzip_and_xz()` — проверяет обычные и сжатые данные.
- `test_damaged_repository()` — проверяет повреждение архивов и кодировки.
- `test_download_index()` — проверяет загрузку с подменой сетевого ответа.
- `test_network_errors()` — проверяет сетевую ошибку, HTTP 404 и тайм-аут.
- `test_local_repository()` — проверяет чтение файла без обращения к сети.
- `test_apt_names_and_versions()` — проверяет допустимые имена и версии APT.

### Этап 3 — `tests/test_graph.py`, класс `GraphTests`

- `test_bfs_visits_levels_and_expands_each_node_once()` — проверяет порядок BFS и однократное раскрытие вершин.
- Вложенная `dependencies()` — возвращает соседей и записывает порядок посещения в этом тесте.
- `test_deduplicate_edges()` — проверяет удаление повторных рёбер.
- `test_test_repository_errors()` — проверяет ошибки JSON и отсутствие корня.
- `test_test_names()` — проверяет имена тестовых пакетов.
- `test_cli_demonstrations()` — проверяет пять случаев в режиме вывода графа.
- `test_apt_transitive_dependencies_root_version_and_cycle()` — проверяет транзитивность APT, версию корня и цикл.
- `test_virtual_package()` — проверяет реализации виртуального пакета.
- `test_missing_transitive_package_reports_error()` — проверяет отсутствующую зависимость.
- `test_real_repository_cli_path()` — проверяет ветку APT в CLI с подменой загрузки.
- `test_missing_root_version_cli_error()` — проверяет отсутствие версии корня через CLI.

### Этап 4 — `tests/test_order.py`, класс `OrderTests`

- `run_cli()` — запускает приложение с выбранным пакетом и значением `load_order`.
- `test_dependency_order()` — проверяет сортировку, приоритет зависимостей и ошибки циклов.
- `test_load_order_cli()` — проверяет пять случаев через CLI и возврат к выводу графа.
- `test_invalid_load_order()` — проверяет недопустимое и пустое значения режима.
