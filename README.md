# ex2_dependency_graph

CLI на Python 3 для построения графа зависимостей Ubuntu APT и вывода порядка загрузки.
Используется только стандартная библиотека, без менеджеров пакетов.

## Запуск

```sh
./run.sh                             # репозиторий из config.ini
./run.sh tests/fixtures/config.ini    # тестовый граф
./tests/run_tests.sh                 # все тесты
```

## Этап 1. Конфигурация

В секции `[settings]` файла INI задаются `package`, `repository`, `test_mode`,
`version`, `ascii_tree`. Ошибки выводятся в stderr, код завершения — 1.
Вывод параметров требовался только на первом этапе; сейчас выводится граф или порядок загрузки.

`src/config.py`:

- `read_settings()` — читает INI и находит секцию настроек.
- `load_config()` — собирает параметры, проверяет их и читает режим `load_order` (по умолчанию `false`).

`src/validators.py`:

- `validate_package()` — проверяет имя пакета APT или имя из больших латинских букв в тестовом режиме.
- `parse_boolean()` — преобразует строковое значение в `True` или `False`.
- `validate_version()` — проверяет формат версии APT.
- `validate_repository()` — проверяет доступность тестового файла или передаёт URL на проверку.
- `validate_repository_url()` — проверяет HTTP/HTTPS URL.

## Этап 2. Сбор данных

`repository` содержит URL индекса `Packages`, `Packages.gz` или `Packages.xz`.
Корневой пакет выбирается по точному имени и версии.

`src/repository.py`:

- `load_repository()` — загружает данные по URL или читает локальный файл.
- `decode_repository()` — распаковывает gzip/xz и декодирует UTF-8.

`src/dependencies.py`:

- `parse_packages()` — разбирает записи индекса APT.
- `find_package()` — находит пакет указанной версии.
- `get_direct_dependencies()` — извлекает прямые зависимости из `Pre-Depends` и `Depends`.

## Этап 3. Транзитивный граф

`src/apt_repository.py`:

- `dependency_names()` — извлекает имена зависимостей, включая альтернативы через `|`.
- `index_packages()` — собирает пакеты и реализации виртуальных пакетов из `Provides`.
- `apt_dependency_reader()` — выбирает версию корня и подготавливает получение соседей.
- Вложенная `get_dependencies()` — возвращает зависимости пакета или реализации виртуального пакета.

`src/graph_repository.py`:

- `parse_test_repository()` — проверяет JSON-граф вида `{"A": ["B"], "B": []}`.
- `test_dependency_reader()` — проверяет наличие корня и возвращает доступ к его связям.

`src/graph.py`:

- `visit_level()` — обрабатывает уровень BFS и рекурсивно переходит к следующему.
- `build_graph()` — запускает обход и возвращает граф достижимых вершин.

Посещённые вершины повторно не раскрываются, поэтому циклы не вызывают
бесконечного обхода. Рёбра циклов сохраняются. При `load_order=false` результат выводится списком
смежности; параметр `ascii_tree` пока только сохраняется в конфигурации.

## Этап 4. Порядок загрузки

В секцию `[settings]` добавлен необязательный параметр `load_order`:
`true` — вывести порядок загрузки, `false` — сохранить вывод графа.
Под порядком понимается последовательность «зависимости перед пакетом»,
включая сам заданный пакет в конце. Файлы пакетов приложение не скачивает.

`src/order.py`:

- `get_load_order()` — выполняет топологическую сортировку алгоритмом Кана:
  сначала берёт вершины без зависимостей, затем освобождает зависящие от них пакеты.
  При цикле сообщает, что линейный порядок невозможен; частичный результат не выводится.

В `tests/fixtures/config.ini` режим уже включён:

```sh
./run.sh tests/fixtures/config.ini
```

Для демонстрации меняется только `package` в этом INI:

| Пакет | Результат |
| --- | --- |
| `A` | `D -> B -> C -> A` — разветвление с общей зависимостью |
| `H` | `J -> I -> H` — цепочка |
| `K` | `K` — без зависимостей |
| `E` | Ошибка: цикл `E -> F -> E` |
| `G` | Ошибка: самозависимость `G -> G` |

### Сравнение с APT

Фактическое сравнение в этой среде не выполнено: APT отсутствует, Docker
не запускается. По согласованию оставлены команды для запуска в Ubuntu 24.04
с архитектурой amd64 и теми же репозиторием и версией пакета, что в INI.
В основном `config.ini` нужно включить `load_order=true`.

```sh
./run.sh
apt-get -s --no-install-recommends install 'bash=5.2.21-2ubuntu4'
apt-get --print-uris --yes --download-only --no-install-recommends install 'bash=5.2.21-2ubuntu4'
```

Первая команда APT показывает план установки без установки пакетов,
вторая — URI архивов без скачивания. Строки `Inst`/`Conf` относятся к установке,
а порядок URI — к скачиванию. Они не обязаны совпадать с топологическим порядком.
Описание опций: [apt-get](https://manpages.ubuntu.com/manpages/noble/man8/apt-get.8.html).

Возможные причины расхождений:

- APT учитывает уже установленные пакеты; программа обходит весь достижимый граф.
- Программа включает все альтернативы и реализации виртуальных пакетов,
  а APT выбирает подходящий вариант с учётом версий, конфликтов и настроек.
- Между независимыми пакетами допустимы разные корректные порядки.
- Для цикла программа выдаёт ошибку. Реальный менеджер может разделять распаковку
  и настройку и разрывать циклические требования при установке; это описано в
  [Debian Policy](https://www.debian.org/doc/debian-policy/ch-relationships.html).

Для `bash` в выбранном индексе есть цикл `libc6 -> libgcc-s1 -> libc6`:
строгий порядок «каждая зависимость раньше пакета» для него невозможен.
Это ограничение топологической сортировки, а не невозможность установки через APT.

## Управление запуском

`src/cli.py`:

- `parse_arguments()` — получает путь к INI из аргументов запуска.
- `print_graph()` — выводит список смежности графа.
- `main()` — читает настройки, строит граф, выбирает вывод графа или порядка загрузки и обрабатывает ошибки.

`src/main.py` — точка входа. В `src/errors.py` определены исключения
`ConfigError` и `RepositoryError`.

Тесты находятся в `tests/`. В `tests/fixtures/graph.json` собраны случаи:
`A` — разветвление, `E` — цикл, `G` — самозависимость, `H` — цепочка,
`K` — без зависимостей. Для демонстрации меняется `package` в тестовом INI.

## Функции тестов

### Этап 1 — `tests/test_main.py`, класс `ConfigTests`

- `setUp()` — создаёт временную папку и исходные настройки для каждого теста.
- `write_config()` — записывает настройки в тестовый INI.
- `run_cli()` — запускает приложение с тестовым графом и выбранным пакетом.
- `test_valid_config_and_cli_output()` — проверяет успешный запуск и вывод графа.
- `test_cli_package_without_dependencies()` — проверяет вывод одиночной вершины.
- `test_cli_missing_test_package()` — проверяет ошибку отсутствующего корня.
- `test_invalid_values_for_every_parameter()` — проверяет недопустимые значения всех параметров.
- `test_missing_and_empty_parameters()` — проверяет пропущенные и пустые параметры.
- `test_local_repository_relative_to_config()` — проверяет путь относительно INI.
- `test_missing_repository_file_and_directory()` — проверяет отсутствующий файл и каталог вместо файла.
- `test_invalid_urls()` — проверяет некорректные URL.
- `test_file_errors()` — проверяет ошибки чтения, структуры и кодировки INI.
- `test_cli_error()` — проверяет сообщение об ошибке, код завершения и отсутствие traceback.

### Этап 2 — `tests/test_dependencies.py`, класс `DependencyTests`

- `setUp()` — читает тестовый индекс APT перед каждым тестом.
- `test_direct_dependencies_of_exact_version()` — проверяет зависимости двух разных версий.
- `test_no_dependencies()` — проверяет пустой список зависимостей.
- `test_missing_package_or_version()` — проверяет отсутствие пакета или версии.
- `test_final_stanza_and_case_insensitive_fields()` — проверяет последнюю запись и регистр названий полей.
- `test_malformed_index()` — проверяет ошибки структуры индекса.
- `test_plain_gzip_and_xz()` — проверяет обычные и сжатые данные.
- `test_damaged_repository()` — проверяет повреждённые архивы и неверную кодировку.
- `test_download_index()` — проверяет загрузку индекса с подменой сетевого ответа.
- `test_network_errors()` — проверяет сетевые ошибки, HTTP 404 и тайм-аут.
- `test_local_repository()` — проверяет чтение локального файла без обращения к сети.
- `test_apt_names_and_versions()` — проверяет допустимые имена и версии APT.

### Этап 3 — `tests/test_graph.py`, класс `GraphTests`

- `test_bfs_visits_levels_and_expands_each_node_once()` — проверяет порядок BFS и однократное раскрытие вершин.
- Вложенная `dependencies()` — возвращает соседей и записывает порядок посещения для этого теста.
- `test_deduplicate_edges()` — проверяет удаление повторяющихся рёбер.
- `test_test_repository_errors()` — проверяет ошибки JSON-графа и отсутствие корня.
- `test_test_names()` — проверяет имена тестовых пакетов.
- `test_cli_demonstrations()` — запускает через CLI разветвление, цикл, самозависимость, цепочку и одиночную вершину.
- `test_apt_transitive_dependencies_root_version_and_cycle()` — проверяет транзитивность APT, версию корня и цикл.
- `test_virtual_package()` — проверяет связи виртуального пакета с его реализациями.
- `test_missing_transitive_package_reports_error()` — проверяет ошибку отсутствующей транзитивной зависимости.
- `test_real_repository_cli_path()` — проверяет ветку APT в CLI с подменой загрузки.
- `test_missing_root_version_cli_error()` — проверяет сообщение CLI об отсутствии версии корня.

### Этап 4 — `tests/test_order.py`, класс `OrderTests`

- `test_dependency_order()` — проверяет порядок для разветвления, цепочки и одиночной вершины, а также ошибки циклов.
- `test_load_order_cli()` — проверяет пять случаев через CLI, коды завершения и отсутствие частичного вывода при цикле.
- `test_invalid_load_order()` — проверяет ошибку недопустимого значения `load_order` в INI.
